## 0. 概述

上一轮的三个缺口已 100% 迁到可执行层，但留下五条残余。本轮把它们逐条闭掉。

**一句话判断**：五条里有**两条是真实能力缺口**（断言只覆盖回测入口、对账只在合成数据上跑过），
**两条是把人读清单变成自动断言**（成交假设/复权、四时点），**一条是知情保留项**（`min_stocks` + docstring）。

本轮不引入新概念，只把已有能力**扩展到该覆盖而没覆盖的地方**，并把一处隐式差异显式化。

## 1. 落点核实（实测，非推断）

用真实缓存数据跑探针，得到三段关键事实：

### 1.1 断言在真实数据上是否误报 —— **不误报**

| 指标 | 实测值（采样 60 只） |
|---|---|
| close_matrix 形状 | 8680 × 60 |
| 索引 | monotonic=True, unique=True, datetime64[ns] |
| NaN 占比 | **50.07%**（真实 A 股截面本就是这个量级） |
| 负价格 / 零价格 | **0 / 0** |
| 全 NaN 列 | **0** |
| `assert_price_panel(真实面板)` | **PASS** |

→ 结论：断言可以安全下移到数据层。上一轮「允许孤立 NaN、只拦必然错误」的设计判断得到实证支持
（若当初断言了 `close > 0` 或「无 NaN」，在 50% NaN 的真实面板上会立刻误报）。

### 1.2 真实数据链路可用性

| 路径 | 状态 |
|---|---|
| `models/oof_predictions.csv` | ✅ 存在（791 列 = 790 票 + date） |
| `strategies/zz500_pit_trial/X_matrix.csv` | ✅ 存在（20 列） |
| `data/cache_meta/hs300_membership.csv` | ✅ 存在 |
| **`strategies/feature_selection/X_matrix.csv`** | ❌ **不存在，但被 `models/portfolio_backtest.py::load_data()` 引用** |

⚠️ **发现**：`models/portfolio_backtest.py::load_data()` 目前是**断的**——它读
`FEATURE_DIR / "X_matrix.csv"`（即 `strategies/feature_selection/X_matrix.csv`），该文件不在仓库中。
即 `python models/portfolio_backtest.py` 会在读 X_matrix 时抛 `FileNotFoundError`。

→ 影响：本轮「对账跑真实数据」的运行器**不能依赖 `load_data()`**，需自行构建数据。
→ 该失效引用是否修复，见 §3 决策点 2。

### 1.3 真实面板上三条实现的可跑性

`build_weight_portfolio` 在真实 60 票面板上跑通：rows=8675，turnover 合计 5550.3，
`port_ret` 无 NaN。→ 对账运行器技术上可行。

### 1.4 既有测试覆盖到哪里

`tests/test_signals_preprocess.py::test_detect_limit_moves` 只有 2 项断言：主板 10% 一字涨停被识别、
创业板 20% 未被误判。**缺**：一字跌停、ST 5%、北交所 30%，以及**撮合层是否真的按掩码拦单**。

## 2. 实施方案

### Phase A — 对账能力复用化（前置重构，~0.5h）

| 动作 | 说明 |
|---|---|
| 新建 `backtest/reconciliation.py` | 把 `reconcile_from_weights`（独立重算账本）与 `assert_closed`（三对账）从**测试文件**提升为公开 API |
| `tests/test_reconciliation.py` 改为 import | 消除「对账逻辑只存在于测试里」的孤岛 |

**理由**：残余 `A2` 需要同一套对账逻辑跑真实数据；逻辑留在测试文件里，离线运行器就得复制一份——
那就出现了第二个真源，正是本项目反复吃过亏的模式。
**验收**：154 项测试仍全绿（纯搬移，行为不变）。

### Phase B — 残余 A1：断言下移到数据层与结果层（~1.5h）

**B1 数据加载层**（`data/fetcher.py`）

- `load_daily` / `download_daily` 在**最终返回前**调用 `assert_price_panel(row, name=...)`（单票 Series 形态已支持）。
- 安全性论证（已实测，§1.1）：真实面板不误报。
- 批量同步不会被拖垮：`sync_index` 已有 `try/except → fail.append`，单票断言失败只会被记入 fail 列表，
  不会中断整批——**确认过，非假设**。
- ⚠️ 断言不得替代既有的降级路径（数据源重试失败返回本地缓存、空数据返回缓存）：
  降级返回的缓存本身也是价格面板，同样适用断言，二者不冲突。

**B2 结果合理性层**

新增 `assert_metrics_sane(metrics: dict, *, name)`，只断言**必然错误**：

| 断言 | 理由 |
|---|---|
| 指标非 NaN / 非 inf | NaN 指标一定是错的 |
| `cum` 末值 > 0 | 净值不可能非正（除非爆仓，届时也应当中断） |
| `turnover ≥ 0`、`cost ≥ 0` | 换手与成本必非负 |
| `port_ret` 非全 NaN | 全 NaN = 输入没对齐 |

⚠️ **明确不加**的一项：**`|SR| > 3` 不进入断言层**。

理由要与 E1 自己的规则一致：「只断言必然成立的性质」。`|SR| > 3` 是**启发式可疑信号**，不是不变量——
夏普 8.75 是 bug，但夏普 3.5 也可能是低波动资产的真实值。把它变成 `raise`，
要么误伤正常研究，要么迫使别人给它开开关——而 E1 刚说过「不设全局开关」。
所以它**保持在 `CLAUDE.md`「数值验证标准」的人工检查清单里**，不进代码。

**B3 顺手修补**：`assert_price_panel` docstring 加一行交叉指引「收益面板请用 `assert_returns_panel`」。
（实测中发现：把收益面板喂给 `assert_price_panel` 会因负收益而误报——函数本身正确，但容易混淆。）

### Phase C — 残余 A2：对账跑真实报告数据（~2h）

**C1 新建 `run_reconciliation.py`**（项目根离线运行器，仿 `run_pit_audit.py` 的「模块 + 运行器 + 测试」三段式）

流程：

```
① 构建真实 close_matrix   ← data/cache/*.csv（symbols 取 oof_predictions 列 ∩ cache）
② 读真实 pred             ← models/oof_predictions.csv
③ 跑 risk.build_weight_portfolio 与 models.build_portfolio（若可达）
④ 调 backtest.reconciliation.assert_closed 对账
⑤ 两实现逐位比对 + 差异定位
⑥ 附带输出 min_stocks ×2 vs ×3 的持仓日差异（供残余 A5 决策）
```

- **不依赖** `load_data()`（已确认其引用失效，§1.2）。
- 输出落 UTF-8 文件，便于复核。

**C2 轻量版进测试**：`tests/test_reconciliation_real_data.py`
- 采样 **50 只真实 cache**（非 790 只），`@unittest.skipUnless(真实缓存存在)`。
- 保留真实 NaN 结构（这是合成数据无法复现的形态）。
- 目标耗时 < 2s。

**为什么不全量进测试套件**：加载 790 只 cache 约 15–30s，会把当前 3.2s 的套件膨胀 10×。
全量走离线运行器，测试套件只保留采样版。

### Phase D — 残余 A3：成交假设与复权的自动断言（~1.5h）

**D1 复权口径** — `tests/test_price_adjust.py`

| 断言 | 目的 |
|---|---|
| `_cache_path(sym,"2") == f"{sym}.csv"`；`"1"`/`"3"` → `f"{sym}_adj{adjust}.csv"` | 锁定映射规则 |
| 三种复权**互不共用文件** | 防前/后复权互相覆盖（铁律 3.5 的核心风险） |
| `load_daily` 与 `download_daily` 使用**同一**映射 | 防「写进 A 文件、读的是 B 文件」 |

**D2 成交假设** — `tests/test_execution_assumptions.py`

- 补齐 `detect_limit_moves` 覆盖：一字跌停、ST（`st_symbols` 传参 → 5%）、北交所（`8`/`4` 开头 → 30%）。
- **新增撮合层断言**（这条才是「成交假设」的实质）：
  - `orchestrator.execute`：不可交易资产维持 `prev_w`，且**方向正确**（涨停禁买、跌停禁卖）。
  - `build_weight_portfolio(trade_limits=...)`：实际持仓 `W_held` 与无限制时**不同**——
    证明掩码真生效，不是摆设。

→ 这是把 `docs/回测语义对照表.md` §2「成交假设」从**人读清单**变成**自动断言**的关键一步。

### Phase E — 残余 A4：四时点齐备断言（~1h）

`tests/test_time_point_contract.py`：构造**手算可验证**的最小场景。

```
价格: [10, 10, 20, 20]      信号: [1, 0, 0, 0]      买 0.026% / 卖 0.076%
```

断言四件事**同时**成立：

| 时点 | 断言 |
|---|---|
| 信号可用 | t=0 的信号**不**产生 t=0 的持仓 |
| 订单生效 | 持仓在 t=1 建立 |
| 成本发生 | t=1 计提买入成本（= 0.026% × 换手） |
| 收益归属 | t=1 收益按 t0→t1（0%）；t=2 吃 t1→t2（+100%） |

对 `engine.run` 与 `build_weight_portfolio` **双双**断言同一手算结果 → 两条实现的时序语义一致。

→ 把现在分散在 `test_no_future_leak` / `test_metrics` / `test_reconciliation` 三处的时点检查，
**收敛为一条端到端契约**。

### Phase F — 残余 A5：参数化 + 措辞（~1h）

**F1 docstring 措辞**（零数值影响）

- `orchestrator.max_leverage` 的 docstring 改为「**总杠杆 `Σ|W|` 上限（gross）**」，
  与实现（`apply_constraints` 用 `w.abs().sum()`）一致。
- 现状 docstring 写「`|sum(W)|` 的绝对值上限」（净敞口）与实现不符——**术语错误，非逻辑错误**。

**F2 `min_stocks` 参数化（不改默认值）**

| 函数 | 新增参数 | 默认 | 行为变化 |
|---|---|---|---|
| `risk/portfolio.py::build_weight_portfolio` | `min_stocks_mult: int = 2` | 2 | **无**（等价原硬编码） |
| `models/portfolio_backtest.py::build_portfolio` | `min_stocks_mult: int = 3` | 3 | **无**（等价原硬编码） |

- 目的：让 `×2 vs ×3` 的差异从**硬编码**变成**显式参数**，使影响可量化、统一变成一行改动。
- `TestKnownDivergence` 升级为：**同一 `min_stocks_mult` 下两实现必须逐位一致**。
  即「钉住一个差异」→「证明差异可消除」。

**F3 影响面量化（只测量，不改结论）**

`run_reconciliation.py` 附带输出：真实 universe 上 `×2` 与 `×3` 的
**持仓日集合差异 + LS 夏普差 + 收益差**。交你决策是否统一。

## 3. 需要审批时明确的决策点

**决策点 1 — 真实数据对账的 pred 口径**

- **A（推荐）**：用**真实 OOF 预测**（`models/oof_predictions.csv`，790 票）+ 真实价格。
  最贴近已发布结论，但需构建 790 票 close_matrix（离线运行，约 20s，一次性）。
- **B**：采样 200 票 + 真实价格 + **合成** pred。快，但 pred 不是真实的，
  对账的是「真实数据形态 + 假信号」，说服力弱一档。

**决策点 2 — `load_data()` 的失效引用是否本轮一并处理**

- **A（推荐）**：本轮**只记录为 TODO**，不修。理由：修它要先回答「哪个 X_matrix 是权威」
  （`feature_selection/` 还是 `zz500_pit_trial/`），这是研究语义问题，不属于本轮范围。
- **B**：本轮先查清 `feature_selection/X_matrix.csv` 的历史去向（git log / 是否被 .gitignore、
  是否曾由某个脚本生成），再决定。

**决策点 3 — `min_stocks` 的最终处置**

- **A（推荐）**：本轮**只参数化 + 量化影响**，不统一。统一与否留给数据说话。
- **B**：量化后若差异可忽略（如持仓日差异 < 1% 且夏普差 < 0.01），本轮直接统一为 `×3`（更严的一侧）。

## 4. 不做的事（明确排除）

| 项 | 理由 |
|---|---|
| `\|SR\| > 3` 进断言层 | 是启发式可疑信号，不是不变量。与 E1「只断言必然成立」冲突，且会引入可被关掉的开关 |
| 真实数据对账进**默认**测试套件 | 790 票 ≈ 15–30s，会把 3.2s 的套件膨胀 10×。走离线运行器 + 50 票采样测试 |
| 修 `load_data()` 的失效引用 | 涉及研究语义（哪个 X_matrix 权威），见决策点 2 |
| 统一 `min_stocks` | 会改变已发布报告持仓日集合，须先量化影响，见决策点 3 |
| L2/L3 订单簿仿真、旁路实时监控 | 红线「不做高频/tick 级」「不接实盘」，沿用上一轮结论 |
