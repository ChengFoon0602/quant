## 0. 判断

对两类工程实践要求（**回测可信度** / **确定性系统**）逐条对照实际代码后，15 条要求分三类：

| 类别 | 条数 | 处置 |
|---|---|---|
| **已在框架内落地** | 8 | 仅在文档中标注「已由 XX 模块承担」 |
| **真实缺口** | 3 | 本次重点 |
| **不适用** | 4 | 与红线冲突，明确排除并说明理由 |

三个真实缺口指向同一个结构性弱点：

> **框架靠「文档约定 + 事后回归测试」保障正确性，缺「事前断言」。**
> 错误只有在有人跑了测试、或结论明显异常（\|SR\| > 3）时才被发现，
> 而不是在数据进入回测的那一刻被拦下。

这与铁律 3 的历史教训同构：`COST_BPS=0.003` 能在 **109 项测试全绿**下存活并污染全部结论，
正因为没有任何一处**在运行时**质疑自己。

## 2. 三个真实缺口（含证据）

### 缺口 A — 确定性内核无断言

```
$ grep -rn '\bassert\b' --include=*.py
→ tests/test_monthly_sampling.py, tests/test_orthogonalize.py,
  models/labels.py, models/linear_baseline.py      （共 4 个文件）
```

`backtest/`、`risk/`、`data/` 的**全部主力路径零断言**。NaN 价格、错序索引、
被篡改的成本参数，都会静默通过。

### 缺口 B — 无回测自洽对账

`grep -rn '对账|reconcil|invariant|闭合|自洽' --include=*.py` → 回测相关零命中。
`port_ret = gross_ret − cost` 这条恒等式、`turnover = Σ|ΔW|`、`cum = Π(1+port_ret)`
**没有任何一处被断言**。三条实现的正确性依赖人工阅读，不依赖机器校验。

### 缺口 C — 语义一致性未显式化

四类语义当前分散在：数据口径（铁律 3.5 / 2）、成交假设（`orchestrator.execute`）、
费用口径（铁律 3 + `risk/cost_model.py`）、时序假设（铁律 1 + 铁律 3 末）。
**缺的不是内容，是一张可核对的单一对照表。**

## 3. 执行结果

### Phase 1 — 断言层 ✅

| 交付 | 说明 |
|---|---|
| `backtest/invariants.py` | `assert_price_panel` / `assert_returns_panel` / `assert_weight_matrix` / `assert_cost_params` / `assert_backtest_inputs`。**零项目内依赖**，显式 `raise`，无全局开关 |
| 接入点（4 处） | `backtest/engine.py::run`、`risk/portfolio.py::build_weight_portfolio`、`risk/orchestrator.py::run`、`models/portfolio_backtest.py::build_portfolio` |
| `tests/test_invariants.py` | 30 项：坏输入必 raise，合法输入不误报 |

**设计要点**

1. 放 `backtest/` 而非 `data/`：`backtest/` → `risk/` 依赖已存在；反向会新增 `data → risk` 边。
2. 模块**零项目内依赖**：若 import `risk.cost_model`，在 `risk/__init__.py` 会形成循环导入。
3. **不提供 `strict=False`**：一个全局开关会退化成第二个 warn 日志。容错由调用点显式 `try/except` 承担。
4. 用**显式 `raise`** 而非 `assert` 语句：`python -O` 会剥离 assert 语句。
5. 只断言**必然成立**的性质，不越界到「通常成立」的判断（如 `close > 0`），避免真实数据误报。

### Phase 2 — 自洽对账 ✅

`tests/test_reconciliation.py`，15 项：

| 对账项 | 断言 |
|---|---|
| 仓位对账 | 持仓满足杠杆 / 单资产上限；列集合与价格矩阵一致 |
| 流水对账 | `turnover == Σ\|ΔW\|`；`cost == buy_turnover·BUY_COST + sell_turnover·SELL_COST` |
| 盈亏核对 | `port_ret == gross_ret - cost`（逐日闭合）；`cum == Π(1+port_ret)` |

**对账方式 = 独立重算**：从 `W_held` 重新推一遍损益与实现给出的结果逐位比对。
不用实现自己的中间量验证实现——那是空转。

**副产品**：跨实现语义比对（`TestCrossImplementationSemantics`）确认
`risk/portfolio.py` 与 `models/portfolio_backtest.py` 对同一输入产出**逐位一致**的损益。

## 5. 执行中发现并钉住的真实差异

### 5.1 `min_stocks` 阈值跨实现不一致（未修改，仅钉住）

| 实现 | 公式 | 默认阈值（`top_q=bottom_q=0.2`） |
|---|---|---|
| `risk/portfolio.py::build_weight_portfolio` | `base * 2` | **10** |
| `models/portfolio_backtest.py::build_portfolio` | `base * 3` | **15** |

其中 `base = max(int(1/top_q), int(1/bottom_q))`。**12 只股票**的截面上：前者开仓
（换手 117.3）、后者空仓（0.0）—— 已实测复现。

定性与处置：

- 除该阈值外，两条实现**逐位一致**（`TestCrossImplementationSemantics` 证明差异被隔离在此一处）。
- 统一它会改变已发布报告的持仓日集合 → **不在本次授权范围**，`TestKnownDivergence` 把差异钉住，
  任何一方改动都会立即失败，迫使做一次有意识的决策。

### 5.2 `orchestrator.max_leverage` docstring 与实现不一致（未修改，仅记录）

docstring 写「`|sum(W)|` 的绝对值上限」（净敞口），实现约束的是 `Σ|W|`（总杠杆）。
标准术语下 `Σ|W|` 才是 gross leverage。修正措辞不影响数值，如需澄清请单独授权。

## 6. 预期收益

把正确性保障从**事后回归**前移到**事前断言**：坏数据在进入回测的那一刻 `raise`，
而不是等到有人注意到夏普异常。与铁律 3 的历史教训形成结构性对冲。
