## 结论

**因子是老老实实手写的，不是从外部拉的现成因子值；但「复现」的保真度没有经受住检验——本质上更接近「按公式意译了一版实现，然后拿去做组合测试」。**

三条判据：

| 维度 | 判定 | 依据 |
|---|---|---|
| 是否本地实现 | ✅ 是 | 191 个 `factor_XXX` 函数共 958 行 + 16 个算子 167 行，零外部因子 API 调用 |
| 是否做过公式对拍 | ⚠️ 做过一次，但证据不可复现 | `tests/cross_validate_alpha191.py` 依赖的参考引擎 `tests/_aurumq_stub` **已不在仓库**，脚本现在 import 即失败 |
| 对拍结果是否合格 | ❌ 不合格 | 留档报告 `tests/alpha191_diff_report.md`：162 个因子 corr < 0.9，大量为负相关；仅 13 个 perfect、2 个 good |

关键区分：`tests/golden/factor_hashes.json` 锁的是**当前实现的输出哈希**，能防"改代码引入回归"，**不能**证明"实现等于研报公式"。它把错误也一起锁住了。

## 一、代码结构：到底实现了什么

```
signals/alpha191/
├── __init__.py      55 行   导出 191 个 factor_XXX + compute_factor_matrix
├── operators.py    167 行   16 个算子（SUM/STD/MAX/MIN/DELTA/DELAY/RANK/TSRANK/
│                            CORR/SMA/REGBETA/REGRESI/COUNT/ABS/LOG/SIGN）
├── factors.py      958 行   191 个因子
└── calculator.py   161 行   批量计算 + 双模式路由
```

调用链（生产路径）：

```
build_pit_matrix.py::build_and_save(ALPHA_FIDS_MOD2)   ← models 主线的特征矩阵
   └─ compute_factor_matrix(790 只, 16 因子)
        ├─ load_daily(sym)              ⚠️ 默认 adjust="2"（前复权）
        ├─ _build_panel(all_dfs)        dict[field] → date×stock 宽表
        └─ 按 _factor_has_rank() 分流
             ├─ True  → fn(panel)       RANK = DataFrame.rank(axis=1)  截面排名
             └─ False → fn(df) 逐股票    RANK = Series.rank()          时序排名
```

因子本身全部是「公式直译 + 算子组合」，例如：

```python
def factor_001(df):
    dlog_vol  = DELTA(LOG(df["volume"]), 1)
    intra_ret = (df["close"] - df["open"]) / df["open"]
    return -CORR(RANK(dlog_vol), RANK(intra_ret), 6)
```

`df` 在两种模式下分别是 `DataFrame`（单股票）或 `dict[str, DataFrame]`（面板），同一份代码同时吃两种输入——靠 `RANK`/`SMA`/`TSRANK` 内部对类型分流实现。

## 二、复现保真度：对拍证据

`tests/alpha191_diff_report.md`（2026-07-26）的分级汇总：

| 类别 | 数量 | 含义 |
|---|---|---|
| perfect (corr>0.999) | 13 | 逐股票完全一致 |
| good (corr>0.95) | 2 | 微小精度差异 |
| minor_diff (0.9~0.95) | 2 | 可接受偏差 |
| **sign_diff (corr<0.9)** | **162** | **方向性分歧** |
| constant / insufficient | 9 | 样本无方差 / 数据不足 |
| stub_ref | 1 | 参考实现是存根 |

也就是说：**177 个走面板比较的因子中，162 个与参考实现对不上，其中相当一部分是负相关（方向相反）。** 报告把它们统一归因为「RANK 语义差异」，但这解释不成立——该版脚本已经用 panel 模式（`rank(axis=1)`）对齐了截面语义，剩下的差异只能来自公式本身。

同时，`tests/alpha191_diff_report.md` 里的「方法论说明」段落仍写着旧版结论（"不进行数值比较"），而脚本源码第 430 行写的是新版（"面板模式比较"）——说明**报告与脚本不是同一版本生成的**，留档本身也失去了可追溯性。

## 三、实测缺陷清单

在真实缓存上跑 191 个因子（panel 模式），得到：

| 现象 | 数量 | 因子 |
|---|---|---|
| 全 NaN | 9 | 043, 044, 045, 046, 109, 111, 113, 114, 117 |
| 输出常数/无方差 | 15 | 097, 099, 101, 102, 105, 121, 123, 125, 126, 129, 133, 135, 137, 138, 141 |
| **合计无效** | **24 / 191（12.6%）** | |
| NaN 比例中位数 | 0.68% | 25 分位 0.41%、75 分位 3.15% |

另有 61 个因子「每日截面唯一值 ≤ 2」。这一项**不能直接判为 bug**——`TSRANK(x,5)` 只有 5 个可能取值，`alpha004` 本来就只有 {+1,−1}，属于公式特性。真正需要看的是 `purify_v2` 的 `cs_effective_ratio`（截面能否成功分 5 组），报告已据此剔除 30 个 CS_eff=0 的因子。

### 3.1 根因 A：前复权价与原始 amount 混用（影响最大）

`compute_factor_matrix` 调用 `load_daily(sym)` 未指定 `adjust` → 默认 `"2"` 前复权。而 `amount` 是**未复权原始成交额**，于是：

```python
panel["vwap"] = panel["amount"] / panel["volume"]
```

得到的 vwap 与复权后的 close **不同量纲**。实测 000001：

| 指标 | 值 |
|---|---|
| vwap / close 中位数 | 1.31 |
| 全样本范围 | 1.025 ~ 4.01 |
| 2020-12-28 实际 | close=15.06，high=15.07，vwap=18.52（**高于当日最高价**） |

比值随时间单调放大（越早的数据越偏离 1），正是前复权累计因子的形状。后果：

1. **`MIN(vwap − price, 0)` 全部恒等于 0** → alpha 097/099/101/102/105/121/123/125/126/129/133/135/137/138/141 退化为常数（与实测的 15 个常数因子高度重合）。
2. **`MAX(vwap − price, 0) ≈ vwap − price`** → 测的不再是日内偏离，而是「该股累计分红送股幅度」。alpha 110/116 就在 models 主线的 16 因子池里。
3. 更严重：前复权因子由**未来**除权事件决定，用它算出的差值天然含前视信息，违反 CLAUDE.md 铁律 3.5（截面因子必须用后复权）。

这是本轮审计最重要的一条：**它不是某个因子的笔误，而是全库 40+ 个 VWAP 类与价格绝对量类因子的共同污染源。**

### 3.2 根因 B：公式转写偏差

| 因子 | 代码 | 问题 |
|---|---|---|
| 043–046 | `LOG(DELTA(volume,1))` | 研报是 `DELTA(LOG(VOLUME),1)`。volume 差分 47% 为负 → `log(负数)=NaN`。实测 `purify_results.csv` 里 **alpha046 只有 5 天有效**（其余 3880 天全 NaN） |
| 010 | `RANK(np.maximum(val, 5))` | 把窗口参数 5 当成逐元素下界。应为 `MAX(val, 5)` = `rolling(5).max()`。等价于算了个「价格平方的截面排名」 |
| 097/109/121/133 | `np.minimum(high−low, 0)` | `high−low ≥ 0` 恒成立 → 结果恒 0 → RANK 全并列 → CORR 分母为 0 → 全 NaN。这是**结构性退化**，与复权无关 |

### 3.3 根因 C：MAX/MIN 语义双关

研报原文里 `MAX(A,B)` 既可能是「逐元素取大」，也可能是「B 日窗口滚动最大」。实现里两种混用：

- `np.maximum(DELTA(close,1), 0)` — 逐元素，合理
- `MAX(vc, 3)` — 滚动 3 日，合理但依赖解读
- `np.maximum(val, 5)` — 逐元素，**错误**

代码里 `np.maximum/np.minimum` 共 65 处，走 `MAX()/MIN()` 算子的只有 3 处（007、019、020）。这种不一致是 162 个因子对不上的主要来源之一。研报本身有歧义（参考实现的 `quality_flag=1` 即标记"论文公式有已知勘误"），但实现没有把每处选择标注下来。

### 3.4 根因 D：RANK 的双语义被调用点绕过

`compute_factor_matrix` 会根据 `_factor_has_rank()` 自动路由到 panel 模式（177 个因子走 panel）。但 **`strategies/scan_alpha191_purify.py` 完全绕过它**：

```python
fn = get_factor_func(fid)
for sym, df in all_dfs.items():
    result = fn(df)          # ← 逐股票，RANK 变成时序排名
```

实测对照（同一天、同一算子）：

| 股票 | panel（截面排名） | per-stock（时序排名） |
|---|---|---|
| 000001 | −0.0400 | −0.2226 |
| 000002 | −0.4800 | −0.4181 |
| 600000 | −0.2400 | −0.7035 |
| 600036 | −0.3200 | −0.4030 |
| 601318 | −1.0000 | −0.5578 |

panel 值是真正的跨股票排序（覆盖 [−1,0] 全区间）；per-stock 值是各股自己在 730 天里的百分位，**跨股票不可比**。v1 扫描脚本（`scan_alpha191_purify.py`）用后者跑完了 191 个因子的全库提纯——其中 177 个的 RANK 语义是错的。v2（`purify_v2.py`）改走 panel 模式，这是唯一正确的全库路径，文件头注释也写了这一点。

## 四、向量化具体怎么做

### 4.1 数据结构：宽表面板替代长表

```python
panel = {field: DataFrame(index=date, columns=symbol) for field in
         ["open","high","low","close","volume","amount"]}
panel["vwap"] = panel["amount"] / panel["volume"]
```

一只股票一列，日期为行。所有算子直接作用在整块矩阵上，**因子函数体内部零逐行循环**。

### 4.2 16 个算子的实现映射

| 算子 | 实现 | 复杂度 |
|---|---|---|
| `SUM/STD/MAX/MIN` | `rolling(n).sum()/.std(ddof=0)/.max()/.min()` | O(N·k) C 实现 |
| `DELTA/DELAY` | `s - s.shift(n)` / `s.shift(n)` | O(N) |
| `RANK` | `DataFrame.rank(axis=1, pct=True)` 截面 / `Series.rank(pct=True)` 时序 | O(N·k log k) |
| `TSRANK` | `rolling(n).apply(searchsorted)` | **O(N·k) Python 回调** |
| `CORR` | `a.rolling(n).corr(b)` | O(N·k) |
| `SMA` | `ewm(alpha=m/n, adjust=False)` 替代递归 | O(N) |
| `REGBETA` | `y.rolling(n).cov(x) / x.rolling(n).var(ddof=0)` | O(N·k) |
| `REGRESI` | `y - REGBETA(y,x,n) * x` | 复用上式 |
| `COUNT` | `cond.astype(float).rolling(n).sum()` | O(N·k) |
| `ABS/LOG/SIGN` | numpy ufunc | 向量化 |

`SMA` 的递归定义 `SMA_t = (m·A_t + (n−m)·SMA_{t−1})/n` 被 `ewm(alpha=m/n)` 精确替代，这是最漂亮的一处——把 O(N) 的 Python 递归换成 C 层指数加权。

### 4.3 两个关键工程处理

**① `_where` 保住索引**

`np.where(cond, x, y)` 对 pandas 对象一律返回 ndarray，后续 `rolling` 会丢掉日期索引、退化成位置对齐。所以包了一层：

```python
def _where(cond, x, y):
    result = np.where(cond, x, y)
    if isinstance(x, pd.DataFrame):
        return pd.DataFrame(result, index=x.index, columns=x.columns)
    ...
```

**② `_factor_has_rank` 用源码扫描做路由**

```python
src = inspect.getsource(fn)
if "RANK(" in src or "TSRANK(" in src or "RANK " in src:
    return True
for helper in ["_ret_rank_pair", "_corr_vol_pair", "_make_regbeta_factor", ...]:
    if helper in src:
        return True
```

结果 177 个因子判为「需 panel」。这个判定**过于粗糙但方向正确**：纯 `TSRANK` 因子两种模式等价（`DataFrame.apply(_tsrank_1d)` 逐列算），走 panel 只是慢；真正不能走 per-stock 的是含 `RANK` 的因子。

### 4.4 性能账

- 面板层：`rolling`/`rank`/`ewm` 全在 C 层，790 只 × 3886 天的单因子在秒级。
- 唯一热点：`TSRANK` 的 `rolling(n).apply` 是 Python 逐窗口回调。CLAUDE.md 已记账：1000×300 的 `ts_argmax` 需 2.5s，真实规模约 13s/算子，全库约 38 个 TSRANK 因子 → 分钟级。目前**未优化**，理由是"零引用时优化是过早优化"。
- 内存：191 因子 × 790 只同时驻留约 5GB，所以 `purify_v2` 按 48 个一批分批计算。

## 六、建议（按性价比排序）

1. **先修 VWAP 量纲**：改用后复权（`load_daily(sym, adjust="1")`）并让 amount 与之匹配；或直接放弃 `amount/volume`，用 `(high+low+close)/3` 作日均价代理。这一步能一次性救回 15 个常数因子中的大部分。
2. **把 `load_daily` 默认复权改掉或显式传参**：目前默认前复权是全局隐患，铁律 3.5 已明令截面因子必须后复权。
3. **补 043–046、010 的公式修正**，并为每处 MAX/MIN 解读加注释说明依据。
4. **删掉或改造 `scan_alpha191_purify.py`**：它现在的输出不可用于任何结论。
5. **重建对拍**：`_aurumq_stub` 已丢失，交叉验证无法复现。要么恢复参考引擎，要么改用独立数据源（聚宽/米筐）抽样 10~20 个因子做真值比对，并把结果写进 CI。
6. **把「24 个无效因子」写成守护测试**：断言每个因子在真实面板上的 `nan_pct < 0.5` 且 `cs_effective_ratio > 0`，坏因子不能静默通过。
