# 回测语义对照表

> 回测的价值不在于「能算出结果」，而在于「算出来的和实盘是同一件事」。
> 本文把四类语义逐项锚定到代码位置，使**口径漂移一眼可见**。
> 对应 `CLAUDE.md` 工程铁律 E3。变更任一口径时，必须同步更新本表。

**英文标题：** Backtest ↔ Live Semantic Parity Table

## 为什么需要这张表

提升回测可信度的**第一层工作是语义一致性，不是参数敏感性**。若回测与实盘的语义本身错位，
那么所有参数优化都是在拟合一个错误的世界——**调得越细，偏离越远**。

拿到一份不理想的结果，第一件事是核对本表，而不是调参、换窗口、加过滤条件。

### 覆盖层下的清算口径（三层账本）

加覆盖层后**单层账本挡不住** —— 账必须拆成三层：

| 层 | 定义 | 代码 |
|---|---|---|
| 仓位账 | `scale × raw_ret`（持仓等比缩放，毛收益与资产级费用同比例缩放） | `close_overlay_ledger()["position_ret"]` |
| 费用账 | `\|Δscale\| × gross × 费率`（调杠杆要再交易一次：增仓按买、减仓按卖） | `["relever_cost"]` |
| 现金账 | `(1 − scale) × 0`（未投入部分按现金处理） | `["cash_ret"]` |

`净收益 = 仓位账 − 费用账 + 现金账`

⚠️ **现金零息是本框架的显式约定，不是事实** —— 若要计货基收益，必须单独建模，
不能塞进这个恒等式。

✅ **已闭合（2026-09-15）**：`risk/drawdown_control.py` 的 `controlled_ret` **就是净收益** ——
三层账已在函数内合成，并以列的形式全部返回（`position_ret` / `relever_cost` / `cash_ret` /
`net_ret` / `cash_weight`）。**净值与回撤也按净收益路径推进**，所以状态反馈与账本一致。

`gross` 是模型假设（该函数只看到收益序列，看不到权重矩阵）：LS 约 2.0、纯多头约 1.0 ——
默认 2.0 对齐本仓库主流的多空口径，**纯多头策略必须显式传 `gross=1.0`**。
`include_relever_cost=False` 保留为**诊断开关**（复现旧的「只记仓位账」口径），生产不用。

**实测（真实 790 票，`mca=0.02 / floor=0.2`）**：闭合口径 net_ret 对账偏差 **0.000e+00**；
只记仓位账则偏差 1.216e-03；费用账合计 **0.1185**、平均现金占比 **0.5520**。
费用账使夏普从 1.8822 降到 **1.7271（−0.155）**。

**已用真实数据验证的闭合**：

| 账本 | 验证 | 结果 |
|---|---|---|
| 原账本（无覆盖层） | `assert_closed` | ✅ 偏差 0 ~ 4.4e-16 |
| **加 `trade_limits` 的受限账本** | `assert_closed` | ✅ 约束不破坏清算恒等（`test_tradability.py`） |
| 覆盖层账本（**默认输出**） | `assert_overlay_closed` | ✅ **偏差 0.000e+00** |
| 覆盖层只记仓位账（诊断开关） | `assert_overlay_closed` | ❌ **按设计失败** —— 此时差额恰为费用账 |
| **Walk-Forward 逐窗拼接** | `reconcile_walk_forward_segments` | ✅ 真实产物 11 窗 / 覆盖 2674 天 / **覆盖率 1.0000** / 非交易日 0 |

### Walk-Forward 拼接层对账（账本对账查不到的一层）

WF 的汇总口径是 `pd.concat([每窗 port_ret]).sort_index()` —— **`sort_index` 会掩盖**
三类问题：窗口**重叠**（同一交易日被计入两次）、窗口**乱序**、索引**重复**。
它们都不会让账本失衡，`assert_closed` 也一无所知，只能在拼接层查。

`reconcile_walk_forward_segments(segments, calendar=...)`：

| 类别 | 内容 | 处置 |
|---|---|---|
| **硬断言** | ① 每段索引唯一且升序 ② 段间两两不相交 ③ 段起点严格递增 | 违反即 raise |
| **报告** | 窗间未覆盖交易日、最长连续缺口、覆盖率、非交易日数 | 只报告 —— 缺口可能来自数据可得性，或**按窗重算的固有热身期丢失** |

调用点：`models/walk_forward.py` 在 `concat` **之前**调用（生成端拦截）；
`run_reconciliation.py` 步骤 ⑤ 对保存产物做完整性复核。

## 已知局限与差异（诚实声明）

**① 涨跌停建模的简化**：创业板/科创板新股上市前 5 日无涨跌停限制、北交所新股首日无限制，
两类未建模，需在更高层用「上市日 + 前 5 日」元数据单独豁免。见 `risk/portfolio.py` 模块 docstring。

> 2026-09-15 另修复一处约束边界：`trade_limits` 的日循环原先从 `i=1` 起，
> 使**首日持仓绕过限制**。该缺口只影响函数返回的 `W_held` 首行，而首行仅作用于被丢弃的
> 建仓爬坡期（`port_ret.iloc[hold_days:]`），**对已发布结果零影响**；该参数此前也无生产调用点。
> 守护测试：`test_execution_assumptions.py::TestExecutionRespectsMask`。
>
> **约束的代价已量化**（`run_tradability_impact.py`，真实 790 票 / 2010-2025 / LS hold_days=5）：
> 加一字涨跌停约束后，换手仅 −0.03%（一字板占比极低：涨停 0.11%、跌停 0.0375%），
> 但**年化 CAGR 19.10% → 17.53%（−1.57pp）、夏普 1.1753 → 1.0924（约 −7%）、
> 最大回撤 −37.17% → −38.79%**。判读：代价温和但不为零（被拦的恰是涨停追涨类交易）。
> `build_trade_limits` 补上了此前无人推导的**前收盘价**环节（`close.shift(1)` 代理，
> ⚠️ 未做除权调整，除权日可能误判）。

**② 成交量上限与冲击成本未建模**：容量检验通过 `return_flows=True` 拿到逐日逐股交易流，
在报告层面估算，不进入回测引擎。这是日线级研究的固有边界。

**③ `min_stocks` 阈值跨实现不一致（已显式参数化 + 已量化影响，**默认值未改**）**：

| 实现 | 参数 | 默认值（`top_q=bottom_q=0.2`） |
|---|---|---|
| `risk/portfolio.py::build_weight_portfolio` | `min_stocks_mult` | **2** → 阈值 10 |
| `models/portfolio_backtest.py::build_portfolio` | `min_stocks_mult` | **3** → 阈值 15 |

其中 `min_stocks = base * min_stocks_mult`，`base = max(int(1/top_q), int(1/bottom_q))`。

**实测影响（`run_reconciliation.py`，真实数据）**：

| 样本 | 开仓日数（×2 / ×3） | 换手合计 | LS 夏普 |
|---|---|---|---|
| 全量 790 票（生产 universe） | 3238 / 3238（**差 0 天，0.00%**） | 2188.8 / 2188.8 | 1.175 / 1.175（差 **0.0000**） |
| 抽样 60 票（稀疏截面） | 1522 / 853（差 669 天，**43.96%**） | 929.7 / 439.4 | 0.570 / 0.560（差 0.0103） |

**结论**：门槛只在「当日有效股数落在 `[base*2, base*3)` 区间」时起作用。真实全量 universe
每日有效股数百余只，两个门槛都轻松满足 → **两条实现逐位一致，差异在生产上不存在**；
只有稀疏截面（每日有效股数 < 15）才会显著。

**处置**：仅参数化（默认行为逐位不变），**不统一** —— 对已发布结论零影响，参数留作稀疏截面的显式开关。
`tests/test_reconciliation.py::TestKnownDivergence` 守护四件事：默认值＝2/3、差异真实存在、
**对齐倍数后逐位一致**、倍数 < 1 必须 raise。

**④ 不做的事**：L2/L3 订单簿仿真（红线「不做高频/tick 级数据」）。保留判断准则：
*观测不到的那部分，若恰好是结论所依赖的，仿真再漂亮也没有验证意义。*

**⑤ `models/` 部分脚本依赖被 gitignore 的生成物（设计取舍，非缺陷）**：
`models/portfolio_backtest.py::load_data()`、`walk_forward.py`、`nn_trainer.py`、
`train_final_model.py`、`linear_baseline.py` 均读取 `strategies/feature_selection/X_matrix.csv`。
该文件是 `build_pit_matrix.py` 的生成物，被 `.gitignore`「特征矩阵」段**有意排除**（大文件不入库）——
在未重新生成的工作副本中不存在。已核实的处置：

- `load_data()` 的报错信息现已指明生成脚本与既存规避方案（`models/rerun_portfolio_backtest.py`）；
- **本表的真实数据对账不依赖它**：`run_reconciliation.py` 直接读
  `models/oof_predictions.csv` + `data/cache/`，因此对账链路完整可用。
