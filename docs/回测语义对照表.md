# 回测语义对照表

> 回测的价值不在于「能算出结果」，而在于「算出来的和实盘是同一件事」。
> 本文把四类语义逐项锚定到代码位置，使**口径漂移一眼可见**。
> 对应 `CLAUDE.md` 工程铁律 E3。变更任一口径时，必须同步更新本表。

**英文标题：** Backtest ↔ Live Semantic Parity Table

## 为什么需要这张表

提升回测可信度的**第一层工作是语义一致性，不是参数敏感性**。若回测与实盘的语义本身错位，
那么所有参数优化都是在拟合一个错误的世界——**调得越细，偏离越远**。

拿到一份不理想的结果，第一件事是核对本表，而不是调参、换窗口、加过滤条件。

## 已知局限与差异（诚实声明）

**① 涨跌停建模的简化**：创业板/科创板新股上市前 5 日无涨跌停限制、北交所新股首日无限制，
两类未建模，需在更高层用「上市日 + 前 5 日」元数据单独豁免。见 `risk/portfolio.py` 模块 docstring。

**② 成交量上限与冲击成本未建模**：容量检验通过 `return_flows=True` 拿到逐日逐股交易流，
在报告层面估算，不进入回测引擎。这是日线级研究的固有边界。

**③ `min_stocks` 阈值跨实现不一致（已钉住，未修改）**：

| 实现 | 公式 | 默认阈值（`top_q=bottom_q=0.2`） |
|---|---|---|
| `risk/portfolio.py::build_weight_portfolio` | `base * 2` | **10** |
| `models/portfolio_backtest.py::build_portfolio` | `base * 3` | **15** |

其中 `base = max(int(1/top_q), int(1/bottom_q))`。在 12 只股票的截面上，前者开仓、后者空仓。
**这不是 bug 的判定，而是口径差异**——统一它会改变已发布报告的持仓日集合，须先评估影响。
`tests/test_reconciliation.py::TestKnownDivergence` 把该差异钉住，任何一方改动都会立即失败。
除该阈值外，两条实现对同一输入产出**逐位一致**的损益（`TestCrossImplementationSemantics`）。

**④ 不做的事**：L2/L3 订单簿仿真（红线「不做高频/tick 级数据」）。保留判断准则：
*观测不到的那部分，若恰好是结论所依赖的，仿真再漂亮也没有验证意义。*

## 变更纪律

改动本表任一行，必须同步：

1. 对应代码位置的实际实现；
2. `CLAUDE.md` 工程铁律 E3、以及既有铁律 1 / 2 / 3 / 3.5 的相关条款；
3. 守护测试（`tests/test_reconciliation.py` / `test_cost_model.py` / `test_no_future_leak.py`）；
4. `README.md` 方法论铁律段落。

**语义一致性是复利**：第一次写清楚，会在后面每一次需求变更时还回来。
