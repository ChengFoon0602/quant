## 定夺原则

优先级按以下权重排序（从高到低）：

1. **是否影响已发布结论**（数据完整性 / 数字口径）—— 最高权重
2. **是否能防止同类 bug 复发**（结构性根因）
3. **收益 / 成本比**（含迭代效率）
4. **工程整洁度** —— 最低权重，且高成本项后置或降级

据此，一个反直觉的排序决定：**「补齐未使用模块的优化」排在最后**，
而「验证基本面 PIT 实现」排在最前——因为前者是优化空气，后者可能触及结论。

## Phase 1 — 数据完整性（约 1–2h，**可能触及已发布结论**）

### 1.1 pit_auditor 接入基本面链路 ⭐ 最高优先级
- **背景**：`zz500_fundamental_trial` 报告明确写了「PIT 对齐从公告日 pubDate+1
  **退化为法定截止日+1**」——这正是前视偏差的经典场景，却从未被独立验证。
- **关键约束（已核实）**：`data/akshare_fundamental_fetcher.py:10` 明确
  「新浪接口只返回报告期，**无公告日**」。因此：
  - ❌ **无法**用该数据源验证「真 PIT」（无 ground-truth ann_date 可比）
  - ✅ **可以**验证「实现是否符合其自称约定」——即以**法定截止日**作为 `ann_date` 代理喂入
    审计器，检查是否有值早于截止日+1 出现在矩阵中（可抓出误用 end_date 的实现 bug）
- **动作**：
  1. 用法定截止日作 ann_date 代理，对基本面特征矩阵跑 `audit_pit_leakage`
  2. 若报 FAIL → 说明实现连退化约定都没遵守，需修数据管线（**会触及结论**）
  3. 若 PASS → 在报告中明确补注：「已验证符合法定截止日+1 约定；但真 PIT 需 tushare
     pubDate，当前数据源不支持，残余偏误方向为保守」
- **验收**：审计结果写入 `strategies/zz500_fundamental_trial/report.md`；结论或补注、或修正。
- **风险提示**：若发现泄漏，方向性结论（「全否定」）可能因前视而失真，需重跑。

### 1.2 年化口径统一
- **问题**：三套并存
  | 位置 | 公式 | 类型 |

  `zz500_pit_trial/report.md` 的年化列需重算。
- **验收**：单一 `annualize()` 工具函数 + 测试断言几何 ≤ 算术（AM-GM 不等式）；

- **注意**：此项会改动已发布数字，若你不希望动历史数字，可退而求其次——
